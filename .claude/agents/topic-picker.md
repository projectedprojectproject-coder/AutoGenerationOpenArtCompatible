# Topic Picker — 주제 선정 기준 (참고 문서)

**이 파일은 더 이상 Agent 도구로 호출되는 서브에이전트가 아니다.** orchestrator가 직접 Read로 읽고, 아래 기준에 따라 **orchestrator 자신이** `topic.json`을 쓴다. (왜 이렇게 바뀌었는지: 서브에이전트 호출은 대화 맥락을 공유하지 않아서, 호출 프롬프트에 주제를 옮겨 적는 걸 빠뜨리면 주제가 통째로 사라진다 — 실제로 이 실수가 세 번 연속 일어나 완전히 다른 주제의 영상이 만들어졌다. orchestrator가 직접 처리하면 이 relay 단계 자체가 없어진다.)

## 언제 이 문서가 필요한가

- **구체적인 주제가 주어졌다**: 이 문서는 필요 없다. orchestrator가 그 주제 문자열을 그대로(요약·순화·재해석 없이) `topic.json`에 옮겨 적으면 끝이다.
- **자유 주제 요청이다** (`anything`/`자유`/`자유주제`/`아무거나`/`free`/`random`/빈 문자열): orchestrator가 이 문서를 읽고 아래 기준대로 **스스로** 주제를 정한다.

## 좋은 숏츠 주제의 기준 (자유 주제 요청일 때만 적용)

- **영상화하기 좋을 것**: AI 비디오 생성 모델(OpenArt/Higgsfield)이 그릴 수 있는 구체적 실사 장면이 떠오르는 소재 — 동물/자연/우주/인체/역사/일상 사물의 "의외의 과학적 이유" 계열이 특히 잘 맞는다 (예: 왜 고양이는 그르렁거리나, 왜 플라밍고는 한 다리로 서나, 왜 문어는 심장이 3개인가, 왜 물에 오래 있으면 손가락이 쭈글쭈글해지나).
- **30초 내외로 설명 가능한 분량**: 너무 거대하거나(우주의 기원) 너무 미묘한(철학적 논쟁) 주제는 피한다.
- **안전하고 무난할 것**: 정치/의료 조언/폭력/선정성/논쟁적 소재는 고르지 않는다.
- **중복 회피**: `shorts-jobs/*/topic.json`을 Glob+Read로 훑어서 이미 다룬 주제와 겹치지 않게 고른다.

주제는 **구체적인 질문/문장 형태**로 정한다 (예: "문어는 왜 심장이 3개나 될까?" — "동물"처럼 막연하게 두지 않는다).

## topic.json 작성 (공통)

```json
{
  "id": "<job_id>",
  "topic": "<전달받은 그대로 / 자유 주제면 정한 주제>",
  "target_duration_s": 30,
  "tone": "흥미/정보",
  "language": "ko",
  "aspect_ratio": "9:16"
}
```

orchestrator가 이미 알고 있는 `target_duration_s`/`language`/`aspect_ratio`가 있으면 그대로 쓰고, 없으면 위 기본값을 쓴다. 정확히 지정된 작업 폴더(`shorts-jobs/<id>/`)에 쓴다.

## 혹시 Agent 도구로 호출됐다면 (레거시 경로)

누군가 이 파일을 여전히 서브에이전트로 호출하는 경우를 대비해 남겨둔다: 호출 프롬프트에 구체적 주제 문자열이나 "자유 주제 요청"이라는 명시가 전혀 없으면, 절대 자유 선정 모드로 넘어가지 마라 — `topic.json`을 쓰지 말고 "호출 프롬프트에 주제가 명시되지 않았다"고 보고하고 멈춰라. 이게 과거 사고의 정확한 재현 조건이다.
